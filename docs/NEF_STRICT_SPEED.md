# 保持成片一致的处理提速验收

2026-10-17，在现有 EXIF 与每轮模型会话基础上，优化逐块推理的数据准备和 JPEG 导出。冻结基线为 `40bfd051e7394c0f393b2c58751fa25f60dde31f`。本轮三组成对整批计时均更快，24 份成片组成的 12 对对照全部逐字节一致；各轮耗时波动明显，不能承诺固定提速比例。

本轮没有调整 tele、额外 EV=0、D50、low/high 选择门限、权重、float32 网络运算、现有 TF32 策略、batch=1、分辨率或 JPEG 质量 95。原始 NEF、既有成片与历史验收目录保留。

## 测量后保留的改动

| 位置 | 改动与边界 |
|---|---|
| `m9/torch_backend.py` | 固定 CUDA 画布新增 uint8 输入/输出接口；CPU/GPU 各复用一个有界 float32 输入缓冲区，保留原 NHWC 存储转 NCHW 视图的步幅。归一化仍为独立减法、除法；输出仍为独立 float32 乘法、加法、ties-to-even round、clip，非有限检查在量化前完成。返回数据不复用输入缓冲区。原 `run()` 接口保留。 |
| `m9/styletrans.py` | 已量化的像素保持 uint8，避免各块反复建立 float32 输入/输出副本。一个 544×544×6 tile 每次清零后复用，仍按 512 步长、16 像素边界、原顺序处理。CPU、非标准画布、浮点 mask 与自定义后端保留原 float32 路径。 |
| `m9/nef.py` | P3 变换保持 128 行分段，复用两个 float32 缓冲区与布尔 mask；保持原矩阵、标量及运算顺序。最终 uint8 缓冲区直接按连续 BGR 排列，避免 OpenCV 对负步幅视图再复制。JPEG、ICC 与 EXIF 写入规则不变。 |

输入缓冲区最多覆盖 864×1120×4 或 544×544×6 的固定网络画布，不缓存全尺寸 GPU 照片，不并发多张。每轮会话销毁时随后端一起释放。CPU 前端本轮保持原样：现有分段工作在线程间重叠，其累计时间不能直接解释为整图瓶颈占比，没有据此加入新的前端实现。

## 一致性与回归证据

成对整批的每一对照片均核对完整 JPEG、压缩 scan、解码 RGB、ICC、EXIF payload、字段值、TIFF 字段类型、方向与实际尺寸，12 对全部相等。输入 NEF、模型权重和候选源码在运行前后相同。JSON 关闭仍保留 EXIF，没有旁路缩图或失败后静默回退。

新增测试检查 P3 float32 位模式、传递函数与裁切边界、128 行分段、非连续输入、JPEG 全字节、归一化、半整数附近的 round、旧输入步幅、输出所有权、非有限值、batch=1、float32 后端兼容及 tile 清零/边缘。6 项 CUDA 严格短例单独排队执行，全部通过；常规测试默认跳过这 6 项，避免与真实照片计时抢占 GPU。

最终完整回归为 **511 passed、6 skipped，16.01 秒**，其中 6 项跳过的 CUDA 短例已单独全部通过。既有失败继续、防覆盖、原子发布、JSON 默认关闭、EXIF 与每轮会话连接测试均保留。产品文件与三组成对计时的 SHA-256 一致。

另外从真实 DSC_1628 的 tele 前端构造固定预览与首个 colorfix tile，使用真实 float32 权重分别运行 high、low、colorfix，比较原 `run(float32)` 和新 `run_u8`：逐元素完全相等，最大绝对差为 0。跨画布切回 high 仍一致，原输入和此前返回的输出未被覆盖；原 `run()` 的 AST 与冻结基线一致，权重哈希相同，关闭会话后 CUDA allocated/reserved 均为 0。这里主动调用 low 只作独立诊断，正式照片仍按原门限选择网络。

### 真实 45MP 与 GUI

使用 `E:\m9input\DSC_0149.NEF`，不是 DX 的 DSC_0150。Z7 II 原始马赛克为 8288×5520，有效区域 `[16,8,8256,5504]`，约 45.44MP；按方向 8 输出 **5504×8256**。冻结基线与候选分别运行 native、DNG，两路各自对照均通过完整 JPEG、scan、RGB、ICC、EXIF 字段值和 TIFF 类型、方向尺寸及管线参数相等；不要求 native 与 DNG 互相相等。每张执行 187 个 colorfix tile；每个版本两张共享一次模型加载。原片哈希前后相同，JSON 关闭，没有半成品，最终 CUDA allocated/reserved 均为 0。该组仅用于正确性验收，不作为成对提速证据。

真实 Tk GUI 使用默认处理器、native/original/auto/JSON 关闭：首轮 3/3 成功，下一轮重新加载模型，运行 DSC_1628 时请求完成当前张后关闭，保存后停止为 1/2，DSC_0192 保持待处理。四份 GUI 成片均与冻结基线严格全字节相等。两轮各 strict create/load 一次，均先关闭会话，再发 finished，线程退出后才销毁窗口，CUDA allocated/reserved 均为 0。心跳最大间隔分别 0.116 秒和 0.039 秒，没有后台 Tcl 警告。
