# NEF 批量队列验收

日期：2026-10-17，Windows 本机。范围为会话内 Tk 队列、串行调度及已有输出接口的集成。双击根目录 `launch_nef_gui.cmd` 使用更新窗口；操作见 [NEF 使用说明](NEF_GUIDE.md)。

## 实现范围

- 多选 NEF、添加当前层文件夹（按文件名排序、不递归）；按规范化绝对路径去重，不按内容合并不同路径。
- 列表显示文件名、来源、状态和结果；空闲后移除待处理项、清空列表；仅重排失败项，手动开始下一轮，成功项不重复处理。
- 每轮固定 method、resolution、device、output_dir、write_json。后台仅发送事件，Tk 主线程更新控件；一次只有一张照片在处理。
- 停止或选择关闭时完成当前张及清理后停止，保留未开始项；线程退出和结束事件都完成后才恢复控件或关闭窗口。
- 单张失败后继续，结束后在列表和日志集中查看失败。进度按本轮已结束任务数计算，成功、失败均计入；另显示整个会话的队列状态。

默认仍为 original、auto、JSON 关闭，保留 main、D50、EV=0、JPEG95、P3、SDR。没有新增曝光、曲线、调色、降噪、人像或模型门限调整。单张 CLI 和 `process_nef()` 未修改，CLI 的 method 默认仍为 dng。

## 自动化

全套 `python -m pytest -q tests`：**170 passed in 10.13s**。随后对按钮文字与说明做一致性调整，GUI/启动器 **22 passed in 3.30s**；这 22 项属于上述测试集，不额外累加成独立总数。

- 调度层 15 项：路径去重、目录排序、串行、失败继续、失败重试、停止/继续、首张/末张边界、固定参数快照、线程启动失败恢复。
- GUI/启动器 22 项：真实 Tk 事件循环响应、主线程更新、忙态禁止修改、两路/两种分辨率/JSON 传递、整体进度和计数、结束事件早于线程退出的竞态、关闭与返回、关闭对话框期间任务已经结束、中文空格路径的启动器转发。
- 输出集成 5 项：使用已有的合成 RAW/替代网络边界，实际执行 `process_nef()` 的 JPEG、ICC、JSON 和发布代码；不同目录同名文件、既有成片/报告保护、中间解码或写盘失败后继续、保存 JPEG/JSON 中途请求停止后仍完成当前对。

输出集成测试没有用合成数据冒充真实网络或真实 NEF。其余既有矩阵、几何、全尺寸、错误与数值测试保留。

## 真实 Tk 与 NEF

新建 `E:\m9output\batch_validation_20261017`，没有覆盖此前样片。查看入口为 **`查看批量验收.html`**；自动化日志为 `pytest_001.log`，逐项处理报告、界面状态、阶段与日志为 `runtime_manifest.json`。JSON 默认关闭仍不妨碍验收工具在独立总记录中留存报告。

主队列通过实际“直接 NEF 处理”按钮连续运行三张，默认 original / auto / JSON 关闭，auto 实际选择 CUDA。窗口由自动化驱动真实 Tk 事件循环：

|---|---|---:|---|
| DSC_0147 | FX / 8256×5504 | 21.18 s | 成功 |

本轮界面计数为 3/3、成功 3、失败 0；总时长 53.36 秒（包括首次依赖加载和界面轮询）。Tk 20 ms 目标心跳实际执行 2186 次，观测最大间隔 0.125 秒。输出文件数与界面计数一致；三张均实际完成三份模型预检和 `StyleTrans=on`。

独立失败场景为“故意损坏的 NEF → DSC_0204 真实 DX NEF”。损坏项明确记录 RAW 解码失败，随后 0204 成功输出 5408×3600，发布前 9.97 秒。该轮 2/2、成功 1、失败 1，没有逐张阻塞弹窗；总时长 13.094 秒、Tk 心跳 538 次，观测最大间隔约 0.078 秒。这里的一次失败是预设故障验证，未伪装为成功或自动切换路径。

四个真实原件处理前后 SHA-256 相同。四份正式 JPEG 均通过文件哈希、完整解码、尺寸、P3 ICC 和内存报告核对；照片旁没有 JSON，没有锁文件或临时残留。进程 RSS 50 ms 采样峰值最大 **4.355 GiB**，CUDA allocator 保留峰值 **1008 MiB**；这些短测不证明长期内存稳定。

## 验收脚本中断与恢复

首次组合脚本在同一进程销毁第一套 Tk、创建第二套 Tk 后，发生 `Tcl_AsyncDelete: async handler deleted by the wrong thread`，进程异常退出。主队列三张已经成功并写好总记录，保留原成片，没有重跑或覆盖它们。

产品入口本身只创建一个 Tk。验收脚本随后按单进程单 Tk 的生命周期，把独立失败场景放入新进程，并在结束前取消脚本自己的心跳计时器；重试正常完成、退出码 0。原始 `runtime_console.log`、恢复 `runtime_resume_console.log`、最初故障输入目录和总记录中的 `validation_interruptions` 均保留。观察到的问题发生于验收脚本切换多个 Tk 解释器时，没有据此擅自修改成像管线。

## 保留与边界

`final_checks.json` 核对了成像及单张接口相关 10 个文件的 SHA-256，与本阶段开始前一致；也逐一核对了上一阶段 **319 个扩测证据文件，全部未变**。当前阶段仅新增队列层、替换窗口交互、增加相关测试和文档。

本轮真实批量仅运行 native/original/auto、JSON 关闭。DNG、phone、JSON 开启的队列参数传递和发布由自动化覆盖；原有两路实拍画质证据见 [实拍验收](NEF_VALIDATION.md)。没有新增真实 DNG 批量、全尺寸 CPU 批量或长时间大队列验证。会话持久化和批量 CLI 不在本阶段范围内。
